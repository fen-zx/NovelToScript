# DECISIONS — 架构决策记录

---

## D-001: 采用 Vue 3 + Element Plus 作为前端技术栈

**日期**: 2026-06-05
**状态**: 已确定
**决定**: 前端使用 Vue 3 Composition API + TypeScript + Element Plus

**原因**:

- Vue 3 是国内主流前端框架，生态成熟
- Element Plus 提供丰富的中后台组件
- TypeScript 保证类型安全，减少运行时错误

---

## D-002: 采用 LangChain Agent 流水线处理小说

**日期**: 2026-06-05
**状态**: 已确定
**决定**: 使用 LangChain 构建 8 个 Agent 流水线：分析→角色提取→情节提取→场景规划→剧本生成→YAML校验→忠实度校验→润色

**原因**:

- 小说转剧本流程复杂，需拆分为多个子任务
- Agent 流水线可逐步处理，每步结果可追溯
- LangChain 提供成熟的 Agent 编排能力

---

## D-003: 剧本输出格式选择 YAML

**日期**: 2026-06-05
**状态**: 已确定
**决定**: 剧本以 YAML 格式输出，并定义正式 Schema

**原因**:

- YAML 可读性强，便于作者直接编辑
- 结构化格式便于程序解析和二次处理
- 相比 JSON 更适合剧本层次结构

## D-013: 采用毛玻璃（Glassmorphism）磨砂质感设计

**日期**: 2026-06-05
**状态**: 已确定
**决定**: 全局 UI 采用毛玻璃磨砂风格：`backdrop-filter: blur(16px)` + 半透明背景 + 四色渐变底色

**原因**:

- 毛玻璃风格现代感强，提升产品视觉品质

- 深色模式下同样适配，深蓝渐变 + 深色磨砂
- HTML 原型已实现验证，纯 CSS 无额外依赖

## D-014: 登录页独立布局（登录前无侧边栏）

**日期**: 2026-06-05
**状态**: 已确定
**决定**: 登录/注册/重置密码页不展示侧边栏和顶栏 Header，采用全屏居中卡片布局；登录成功后通过 `body.logged-in` 类切换显示侧边栏

**原因**:

- 未登录用户无需看到导航栏，减少视觉噪音
- 全屏居中布局聚焦认证操作，提升转化率
- CSS opacity + pointer-events 切换，无需额外路由判断

---

## D-008: 章节识别采用五级兜底策略

**日期**: 2026-06-05
**状态**: 已确定
**决定**: 章节识别按优先级依次尝试：规则匹配(内置+自定义正则)→目录识别→AI辅助→按长度切片→人工确认

**原因**:

- 小说章节格式多样，单一策略覆盖率不足
- 自定义正则让用户可适配特殊格式（如 `^\【.*\】$`）
- AI 兜底保证极端情况可用
- 人工确认确保最终准确性

---

## D-009: 前端采用 localStorage + IndexedDB 四级离线缓存

**日期**: 2026-06-05
**状态**: 已确定
**决定**:

- localStorage: 用户配置、任务状态
- IndexedDB: 小说原文、YAML 草稿、生成结果
- 四级缓存：草稿缓存(必须) → 编辑器自动保存 → 任务状态恢复 → 生成结果缓存

**原因**:

- 长文本编辑场景需防止意外丢失
- IndexedDB 支持大文本存储（单文件可达 20MB）
- SSE 断连后可恢复任务状态

---

## D-010: 文本分片采用三级策略

**日期**: 2026-06-05
**状态**: 已确定
**决定**: 章节分片 → 章节内切片(超8000字按段落边界) → 语义切片(保持完整性)，单次 Agent 输入 5000~8000 字

**原因**:

- LLM 上下文窗口有限
- 章节为自然边界，优先使用
- 语义切片避免截断对话/场景

---

## D-011: 文件存储生命周期管理

**日期**: 2026-06-05
**状态**: 已确定
**决定**:

- 原始文件 + 中间文件: 保留 30 天后自动清理
- 最终剧本: 长期保存
- 单用户存储上限: 500MB
- 单文件上限: 20MB

**原因**:

- 中间文件仅用于断点重试，无需长期保留
- 最终剧本是核心产物需永久保存
- 500MB 限制防止存储滥用

---

## D-012: Schema 多版本共存 + extensions 扩展区

**日期**: 2026-06-05
**状态**: 已确定
**决定**:

- Schema 支持版本号管理，旧版本剧本不受新 Schema 影响
- 在 Schema 中预留 `extensions` 字段，允许作者注入自定义属性

**原因**:

- 避免 Schema 升级导致历史剧本校验失败
- extensions 提供扩展灵活性，满足不同剧本类型的特殊需求
