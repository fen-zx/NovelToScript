# 设计文档生成器（DesignGenerator）

## 目标

将 RequirementAnalyzer 输出的结构化需求，转化为可直接用于开发的页面设计文档，包含布局规划、组件拆分、数据流向，作为前端编码和设计评审的依据。

## 何时使用

- 拿到结构化需求后，需要将"做什么"变成"怎么做"
- 需要为新页面规划 Vue 组件树和目录结构
- 前后端协作时，需要明确每个模块的数据来源（哪个接口、哪些字段）
- 想在编码前对页面布局有一个全局概览

## 输入

| 输入项     | 必填 | 说明                                                                 |
| ---------- | ---- | -------------------------------------------------------------------- |
| 结构化需求 | ✅   | RequirementAnalyzer 输出的 JSON（`pages[].modules[].features/data`） |
| 设计风格   | 可选 | `简洁` / `企业` / `移动端`，默认 `企业`                              |

### 风格预设

| 风格   | 布局特征                            | 典型场景                      |
| ------ | ----------------------------------- | ----------------------------- |
| 简洁   | 单列布局、大量留白、卡片式          | Dashboard、数据看板、内部工具 |
| 企业   | 侧边导航 + 顶栏、表格密集、弹窗编辑 | 管理系统、ERP、数据平台       |
| 移动端 | 单列堆叠、底部 Tab、下拉刷新        | H5、小程序、混合 App          |

## 输出格式

输出为 Markdown 文档，可直接保存为 `PAGE_SPECS.md`。

```markdown
# PRD 设计文档

> 基于 RequirementAnalyzer 输出自动生成
> 风格：企业

---

# 页面: {页面名称}

## 功能说明

{一段自然语言描述该页面的核心功能}

## 页面布局

+------------------------------------------+
| 顶栏: Logo + 用户头像 + 退出 |
+------------------------------------------+
| 搜索栏: 姓名输入框 + 状态下拉 + 搜索按钮 |
+------------------------------------------+
| 表格区: 用户列表 (姓名|邮箱|状态|操作) |
+------------------------------------------+
| 分页器 |
+------------------------------------------+

## 建议组件

| 组件名        | 类型     | 功能                         | 复用性 |
| ------------- | -------- | ---------------------------- | ------ |
| SearchForm    | 业务组件 | 搜索表单，支持姓名/状态筛选  | 低     |
| UserTable     | 业务组件 | 用户数据表格，含排序、操作列 | 低     |
| EditUserModal | 业务组件 | 编辑用户弹窗，含表单校验     | 中     |

## 数据来源

| 模块     | 数据字段                   | 来源接口                   | 请求方式 |
| -------- | -------------------------- | -------------------------- | -------- |
| 用户列表 | 姓名、邮箱、状态、注册时间 | `/api/users`               | GET      |
| 用户列表 | 搜索条件                   | `/api/users?name=&status=` | GET      |
| 编辑用户 | 姓名、邮箱、状态           | `/api/users/:id`           | PUT      |

## 交互说明

### 搜索

- 触发方式：点击"搜索"按钮 / 回车
- 行为：携带筛选条件重新请求 `/api/users`
- 边界：搜索无结果时展示空状态插画 + "暂无数据"

### 编辑

- 触发方式：点击表格操作列的"编辑"按钮
- 行为：弹出 EditUserModal，表单回填当前行数据
- 校验：姓名必填（2-20 字）、邮箱格式、状态必选
- 提交后：关闭弹窗、刷新列表、Message 提示"保存成功"
```

## 生成规则

### 布局生成

1. 根据风格预设选择容器模式（侧边导航 vs 顶部导航 vs 单列）
2. 按功能点的交互类型映射布局区域：列表 → 表格区，搜索 → 搜索栏，新增/编辑 → 弹窗或独立页面
3. 用 ASCII 图示意大致布局（不追求像素级准确）

### 组件建议

1. 优先复用项目已有的全局组件（检查 `src/components/` 目录）
2. 业务组件以功能命名，通用组件以 UI 特征命名
3. 标注复用性：`高`（跨页面复用）/ `中`（同页面多处）/ `低`（单处使用）
4. 若项目使用 Element UI / Ant Design，优先建议其内置组件

### 数据来源映射

1. 查看项目 `src/api/` 目录下的已有接口定义
2. 对新接口给出 RESTful 路径建议和方法
3. 字段名与需求中的 `data` 字段一一对应

### 交互说明

1. 每个功能点标注触发方式、行为路径、边界处理
2. 涉及表单的需列出校验规则
3. 涉及异步操作的需标注 loading 和错误处理

## 工作步骤

1. **解析需求**：提取所有 pages、modules、features、data
2. **选择风格**：用户指定或根据场景推断（管理系统 → 企业，H5→ 移动端）
3. **生成布局**：为每个页面绘制 ASCII 布局草图
4. **拆分组件**：列出组件清单，标注复用性和数据依赖
5. **映射数据来源**：关联已有接口或建议新接口
6. **编写交互说明**：覆盖正常流、异常流、边界
7. **建议目录结构**：给出 `src/views/` 下的文件组织
8. **汇总疑问**：设计过程中发现的模糊点放入"待确认"

## 注意事项

- 组件拆分粒度以"单一职责"为准，避免一个组件做太多事
- 布局 ASCII 图保持简洁，不超过 15 行
- 数据来源映射要实际检查 `src/api/` 目录，不要凭空编造接口
- 与 `requirement-analyzer` 和 `business-logic-checker` 保持数据格式兼容，可形成链式工作流
