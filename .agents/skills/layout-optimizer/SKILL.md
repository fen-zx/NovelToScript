# 布局优化器（LayoutOptimizer）

## 目标

从信息架构、用户体验、视觉结构、响应式、开发复杂度五个维度评估页面布局，识别具体问题并给出可直接替换的优化后布局方案。

## 何时使用

- ASCII 布局生成后，进入原型前做一次快速评审
- 低保真原型完成后，验证交互路径是否合理
- 高保真设计走查时，作为补充性结构评审
- AI 生成代码前，最后的一道"布局是否合理"卡控

## 输入

| 来源 | 格式 | 适合场景 |
|------|------|----------|
| AsciiLayoutGenerator 输出 | Markdown ASCII 图 | 早期快速评审 |
| LowFiPrototypeGenerator 输出 | Markdown 原型说明 | 含交互流程，可做操作步数分析 |
| 自定义 ASCII 图 | 文本 | 手绘或团队协作的布局草图 |
| Figma 导出结构 | JSON / 截图描述 | 高保真走查 |

## 问题列表

### 🔴 问题1：搜索区域过于靠下
- **维度**：信息架构 / 用户体验
- **现象**：搜索栏位于表格下方
- **影响**：用户首次进入页面难以发现搜索入口，需滚动才能筛选
- **建议**：将搜索区域移至 Header 与表格之间
- **扣分**：-6（信息架构 -3 / 用户体验 -3）

### 🟡 问题2：操作栏按钮过多（5 个平级按钮）
- **维度**：视觉结构 / 用户体验
- **现象**：操作栏同时展示 [新增] [导入] [导出] [批量删除] [刷新]
- **影响**：视觉噪音大，用户决策负担重
- **建议**：保留 2 个主按钮，其余收入 [更多 ▼] 下拉菜单
- **扣分**：-4（视觉结构 -2 / 用户体验 -2）

### 🟢 建议1：表格缺少空状态提示
- **维度**：用户体验
- **现象**：未定义无数据时的展示
- **影响**：空列表时用户看到空白区域，不确定是加载失败还是确实无数据
- **建议**：增加空状态插画 + "暂无数据，[新增第一条]"

## 检查维度详解

### 1. 信息架构（权重 30%）

| 检查点 | 评分标准 |
|--------|----------|
| 模块顺序 | 是否符合用户操作流程（筛选→列表→详情） |
| 信息层级 | 主次区域是否明确区分（核心内容占 >60% 空间） |
| 内容聚类 | 相关功能是否放在同一区域（不跨区域跳跃） |
| 导航可见性 | 关键入口在首屏是否可见 |

**常见扣分场景**：
- 搜索栏在底部 → -5
- 关键操作需要滚动才能看到 → -4
- 相关内容分散在两个不相邻区域 → -3

### 2. 用户体验（权重 30%）

| 检查点 | 评分标准 |
|--------|----------|
| 操作路径长度 | 核心操作 ≤ 2 步（点击→弹窗→提交） |
| 点击目标大小 | 按钮/链接密度是否合理（不拥挤） |
| 表单复杂度 | 单次表单字段数 ≤ 7，超出需分步或分组 |
| 操作反馈 | 每个操作是否有明确的成功/失败/加载态 |

**常见扣分场景**：
- 表单字段 > 10 个且未分组 → -4
- 操作后无反馈 → -3
- 按钮间距太密（<8px 等效）→ -2

### 3. 视觉结构（权重 20%）

| 检查点 | 评分标准 |
|--------|----------|
| 主次关系 | 主要操作 vs 次要操作是否视觉区分 |
| 空间利用率 | 无大面积空白或过度拥挤 |
| 模块密度 | 单屏模块数建议 3~7 个 |
| 对齐一致性 | 同层元素是否左对齐/居中对齐统一 |

**常见扣分场景**：
- 主要操作和次要操作样式相同 → -3
- 单屏模块 > 10 个（信息过载）→ -3
- 大面积空白无内容 → -2

### 4. 响应式（权重 10%）

| 检查点 | 评分标准 |
|--------|----------|
| 移动端兼容 | 表格是否有横向滚动方案 |
| 平板兼容 | 两栏布局是否可折叠为单栏 |
| 桌面端兼容 | 宽屏是否合理利用（不拉伸过度） |

**常见扣分场景**：
- 固定宽度表格，无横向滚动方案 → -3
- 侧边栏在移动端未隐藏 → -2

### 5. 开发复杂度（权重 10%）

| 检查点 | 评分标准 |
|--------|----------|
| 模块复用率 | 是否复用了项目已有组件 |
| 组件数量 | 页面组件数是否合理（5~15 个） |
| 状态复杂度 | 页面状态数是否可控（≤ 8 种） |

**常见扣分场景**：
- 存在可合并为通用组件的重复模块 → -2
- 状态数 > 10（测试成本高）→ -2

## 评分规则

### 总分计算

```
总分 = Σ(维度得分 × 权重)
```

### 分级标准

| 评分区间 | 等级 | 建议动作 |
|----------|------|----------|
| 90-100 | 🟢 优秀 | 无需调整，直接进入原型 |
| 75-89 | 🟡 良好 | 修复 🔴 严重问题后进入原型 |
| 60-74 | 🟠 需改进 | 修复 🔴+🟡 问题，重新评审 |
| < 60 | 🔴 不合格 | 重新设计布局方案 |

### 问题分级

| 标记 | 含义 | 示例 |
|------|------|------|
| 🔴 严重 | 直接影响核心任务完成 | 搜索不可见、保存按钮在屏幕外 |
| 🟡 建议 | 影响效率或体验 | 操作步数多、按钮未分组 |
| 🟢 优化 | 锦上添花 | 空状态提示、快捷键标注 |

## 工作步骤

1. **解析布局**：提取所有模块及其顺序、类型、包含的元素
2. **逐维度打分**：按五个维度依次检查，记录每个扣分点及原因
3. **计算总分**：按权重汇总得出百分制评分
4. **列出优点**：识别布局中做得好的 3~5 个点（有助于团队保留有效设计）
5. **分级问题**：按 🔴🟡🟢 排序输出问题列表，每条包含：维度、现象、影响、建议、扣分
6. **生成优化布局**：将所有建议合并，输出一份"优化后"的 ASCII 布局图
7. **输出变更摘要**：表格化列出所有变更点和类型

## 常见问题模式库（快速匹配）

| 模式 | 特征 | 标准建议 |
|------|------|----------|
| 搜索沉底 | 搜索栏在内容区下方 | 上移至 Header 与内容之间 |
| 按钮风暴 | 操作栏 ≥ 4 个平级按钮 | 主次分离，次要收入"更多"菜单 |
| 表单过长 | 单个表单 > 10 字段 | 分组 + 折叠，或分步向导 |
| 表格无状态 | 只画了表格，无空/加载/错误态 | 补充 3 种状态占位 |
| 右栏孤儿 | 侧边栏内容与主区域无关联 | 检查是否可合并，或标注轻量级内容 |
| 无返回路径 | 深层页面无面包屑/返回按钮 | 添加面包屑或顶部返回按钮 |

## 注意事项

- **必须有评分**：每个维度都要打分，不能只给总分
- **扣分必须归因**：每条扣分说明属于哪个维度、扣了多少
- **优化布局必须可替换**：输出的 ASCII 图应是原图的直接替代，而非全新设计
- **不涉及视觉美化**：不评价颜色、字体、圆角——只关注结构和交互
- **与 `business-logic-checker` 互补**：前者检查"逻辑对不对"，本 Skill 检查"布局好不好"
- 与 `requirement-analyzer` → `design-generator` → `ascii-layout-generator` → `lowfi-prototype-generator` 保持数据格式兼容
