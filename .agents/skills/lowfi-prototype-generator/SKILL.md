# 低保真原型生成器（LowFiPrototypeGenerator）

## 目标

将 DesignGenerator 的页面规格和 AsciiLayoutGenerator 的布局图，转化为统一格式的低保真原型描述文档——包含组件清单、交互流程、状态矩阵——作为 Figma、Excalidraw、Whimsical 等原型工具的输入蓝图。

## 何时使用

- ASCII 布局确认后，需要细化每个区域里有什么
- 产品评审时需要一份"比线框图更具体、比高保真更轻量"的原型说明
- 需要为 Figma / Excalidraw 生成结构化输入（组件 + 交互 + 状态）
- 前后端对齐：前端知道该画什么状态，后端知道要返回哪些状态对应的数据

## 输入

| 来源 | 格式 | 说明 |
|------|------|------|
| DesignGenerator 输出 | Markdown PAGE_SPECS | 含组件建议、数据来源，最佳 |
| AsciiLayoutGenerator 输出 | Markdown ASCII 图 + 布局说明 | 含模块排列顺序 |
| RequirementAnalyzer 输出 | JSON | 仅含功能点，组件推断较粗糙 |

## 输出格式

Markdown，可直接作为原型工具的设计输入。

## 交互流程

### 搜索
```
用户输入姓名 / 选择状态
        ↓
点击 [搜索] 或按 Enter
        ↓
GET /api/users?name=xxx&status=xxx
        ↓
   ┌─ 成功 → 刷新表格，更新分页
   └─ 失败 → Toast "搜索失败，请重试"
```

### 编辑用户
```
点击表格行 [编辑]
        ↓
弹出 EditUserModal（回填当前行数据）
        ↓
用户修改字段 → 点击 [保存]
        ↓
   ┌─ 校验通过 → PUT /api/users/:id → 成功 → Toast "保存成功" → 关闭弹窗 → 刷新列表
   └─ 校验失败 → 字段标红提示
```

### 删除用户
```
点击表格行 [删除]
        ↓
弹出确认框："确定删除用户 xxx 吗？"
        ↓
   ┌─ 确认 → DELETE /api/users/:id → 成功 → Toast → 刷新列表
   └─ 取消 → 关闭确认框
```

## 页面状态矩阵

| 状态 | 触发条件 | 搜索区域 | 表格区 | 分页器 | 弹窗 |
|------|----------|----------|--------|--------|------|
| 初始 | 页面首次加载 | 默认空值 | 加载中骨架屏 | 隐藏 | 隐藏 |
| 加载中 | 请求进行中 | 可交互 | Skeleton/Spin | 隐藏 | — |
| 有数据 | 请求成功返回数据 | 正常 | 数据行 | 正常显示 | — |
| 空数据 | 请求成功但无结果 | 正常 | 空状态插画 + "暂无数据" | 隐藏 | — |
| 搜索无结果 | 筛选后无匹配 | 保留条件 | "未找到匹配用户" | 隐藏 | — |
| 网络错误 | 请求超时/500 | 正常 | "加载失败，[重试]" | 隐藏 | — |
| 编辑弹窗 | 点击编辑 | 不可交互(遮罩) | 不可交互 | 不可交互 | 显示 |
| 删除确认 | 点击删除 | — | — | — | 确认框 |

## 生成规则

### 组件推断
1. 从 DesignGenerator 的"建议组件"中提取组件名和类型
2. 为每个组件列出属性：输入框→placeholder，下拉→选项，表格列→数据类型+宽度
3. 若输入的只是 ASCII 布局，根据模块名称推断组件（"搜索区域"→Input+Select+Button）

### 交互流程生成
1. 每个功能点生成一条流程：**触发 → 请求 → 分支（成功/失败）→ UI 响应**
2. 使用 ASCII 箭头图展示，每个分支有明确 UI 结果
3. 覆盖正常流 + 异常流（校验失败、网络错误）

### 状态矩阵生成
1. 每个页面至少覆盖 8 种状态：初始、加载中、有数据、空数据、搜索无结果、网络错误、弹窗、确认框
2. 用表格展示每个状态下各区域的表现
3. "—"表示该区域不受此状态影响

### 组件树生成
1. 按页面→区域→组件→子组件的层级缩进
2. 标注组件类型和关键属性
3. 弹窗/抽屉等浮层作为独立子树

## 工作步骤

1. **解析输入**：提取页面名称、模块列表、组件建议、数据字段
2. **生成组件清单**：为每个模块列出组件、类型、属性
3. **绘制交互流程**：为每个 feature 生成触发→请求→分支→响应的 ASCII 图
4. **构建状态矩阵**：覆盖 8 种核心状态，标注每区域表现
5. **组装组件树**：按层级缩进输出完整组件结构
6. **添加适配提示**：针对 Figma / Excalidraw / Whimsical 给出转换建议

## 注意事项

- 低保真 = 只描述"有什么、怎么交互、有哪些状态"，不涉及颜色/圆角/阴影/动画
- 交互流程必须覆盖异常分支，不能只有"成功"一条线
- 状态矩阵中"空数据"和"搜索无结果"是两个不同状态，UI 文案应有区别
- 组件树中的弹窗/确认框是浮层，不嵌套在页面组件树内，单独列出
- 与 `requirement-analyzer` → `design-generator` → `ascii-layout-generator` → `business-logic-checker` 保持数据格式兼容
